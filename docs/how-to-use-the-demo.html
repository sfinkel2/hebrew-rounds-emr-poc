1. Start the app

In a terminal, from the project folder C:\Practicum\Practicum_2:

npm start

Then open http://localhost:3000 in Chrome. Every npm start reseeds the patient record, so each rehearsal begins from the same clean slate.

No keys needed. Leave .env keys blank and the whole demo runs offline on canned, deterministic data — the most reliable way to present in class. (Add API keys only if you want the live microphone + live AI path.)

2. Check the mode badge (top-right)

Before you start talking, glance at the badge in the top-right corner so you know which path you're on:

BadgeMeaning
● מצב MOCK (לא מקוון)Mock / offline. Uses the scripted Hebrew round and canned AI output. Deterministic — recommended for the demo.
● מצב LIVE (Whisper + Claude)Live. Real OpenAI Whisper transcription + real Claude structuring/judging. Needs API keys.
● שגיאת חיבורConnection error — the server isn't reachable. Make sure npm start is running.

3. The screen layout

The page is one screen with three areas, following the numbered stepper at the top (1 · הקלטה / תמלול → 2 · מבנה ובדיקה → 3 · רשומת כמליאון):

  • Patient header — the post-op patient: David Cohen / דוד כהן, age 58, day 2 after a small-bowel resection.
  • Capture (left, modern) — לכידת הסבב — record or load the round and see the Hebrew transcript.
  • Review & approve (right, modern) — סקירה ואישור — the AI-structured note, field by field, with the safety checks.
  • Chameleon EMR (bottom, deliberately legacy 90s look) — the mock hospital record the approved note lands in, plus an audit log. The retro styling makes the point: we plug into the systems hospitals already use.

4. Step-by-step walkthrough

1

Load the round

In the Capture panel, click השתמש בסבב מתוסרט (Use scripted round). The Hebrew round transcript appears in the transcript box on the right of that panel.

Live alternative: click הקלט סבב (Record round), allow the microphone, speak the round in Hebrew, then click עצור הקלטה (Stop recording). (Only works in LIVE mode with a key; the scripted button is the safe choice on stage.)

2

Structure & check the note

Click the green בנה הערה ובדוק ← (Structure note & check) button. Behind the scenes this runs three things in order: the AI extracts each field with the exact quote that supports it, a separate adversarial AI "judge" re-checks every field against the transcript, and deterministic code guardrails run.

The Review panel fills with field cards grouped by section (subjective, exam/vitals, plan, decisions). See §5 for how to read a card.

3

Approve the good fields

For each correct field, click ✓ אשר (Approve). To discard one, click ✕ דחה (Reject). You can edit a value inline first — its status changes to נערך (edited) and the original is kept in the audit trail.

4

Handle the flagged fields (the key moment)

Two fields are deliberately flagged — this is your safety story (§6). A flagged field's ✓ אשר button is disabled until you address the warning by clicking אשר ידנית (Confirm manually). The warning row then shows ✓ אושר לאחר בדיקה (confirmed after review) and Approve unlocks.

5

Commit to the EMR

The בצע קומיט מאושר ← כמליאון (Commit approved → Chameleon) button stays disabled until at least one field is approved — that's the hard human-in-the-loop gate. Click it, and the approved fields drop into the legacy Chameleon record at the bottom, with each write logged in the Audit Log (click Audit Log in the retro toolbar to show it).

5. Reading a field card

Each card packs the whole safety story into one view:

ElementWhat it tells you
Field labelHebrew name + English subtitle (e.g. תרופות / Medications).
Confidence chipA % with color — how sure the extractor was. green = high, amber = medium, red = low.
Source quoteמקור מהתמלול (source from transcript) shows the exact Hebrew words that justify the value. If grounding fails, it reads ✕ מקור שלא נמצא בתמלול (source not found in transcript).
Judge verdictgrounded · ungrounded · contradicted · ambiguous — the independent AI judge's call.
Warning rowAppears when a guardrail requires a human check (ungrounded, or a high-risk order). Holds the אשר ידנית (Confirm manually) button.
Status pillממתין pending · אושר approved · נדחה rejected · נערך edited.
Actions✓ אשר Approve · ✕ דחה Reject.

6. The safety moment — what to point at

This is why the demo matters. Two cards are engineered to fail safely:

A. The hallucination that gets blocked — Temperature / חום The AI tried to record "no fever" (אין חום) — but no one ever said that in the round. The grounding guardrail catches it: the card shows ✕ מקור שלא נמצא בתמלול, the judge marks it ungrounded, and you cannot approve it without an explicit override. This is the malpractice-prevention story — an invented clinical fact stopped before it reaches the chart.
B. The high-risk order that forces a second look — Medications / תרופות The opioid order morphine 4 mg IV (מורפיום 4 מ"ג IV) was captured correctly and is grounded — yet because medications are high-risk, the guardrail still forces a manual אשר ידנית confirmation before it can be approved. The point: even when the AI is right, dangerous fields always get a human's eyes.
C. The hard gate Nothing reaches the Chameleon EMR automatically. The Commit button is dead until a human approves, and every committed value is written to the audit log with its source quote, the judge's verdict, and the approver. That's the whole "no clinical information entered incorrectly" claim, made visible.

7. Presenter talk-track (~3 min)

Optional script — say this while clicking:

[Show the legacy EMR] "This is the kind of EMR a hospital ward actually runs — Chameleon. Right now this patient's round note is nearly empty, and a resident would spend their morning re-typing it by hand."
[Click "Use scripted round"] "Instead, the round is just spoken — in Hebrew. Here's the transcript of the attending walking the team through this post-op patient."
[Click "Structure note & check"] "Our system structures it into the exact ward-note fields — and crucially, every field carries the exact quote it came from, plus an independent AI judge that re-checks it, plus hard-coded safety rules."
[Point to the Temperature card] "Watch this one. The AI tried to write 'no fever' — but nobody said that. The system catches it as ungrounded and refuses to let it through. That's the error that, missed, becomes a lawsuit."
[Point to the Medications card] "And this opioid order is correct — but because it's high-risk, we still force a human to sign off. Right when the AI is right, we don't get complacent."
[Approve good fields, confirm the flagged one, click Commit] "The clinician approves, and only then does it flow into Chameleon — with a full audit trail of who approved what and why. Documentation that took an hour now takes a minute, and it's safer than before."

8. Reset & troubleshooting

SituationDo this
Want a clean record for the next runStop and re-run npm start (auto-reseeds), or run npm run reset.
Badge shows ● שגיאת חיבורThe server stopped. Re-run npm start and refresh the page.
Microphone button does nothing / errorsMic + live transcription only work in LIVE mode (keys set). For the demo, use השתמש בסבב מתוסרט (scripted round).
Hebrew looks reversed/oddUse Chrome; the page is built for right-to-left and renders best there.
Want to prove it's solidRun npm test — 14 automated checks of the guardrails, commit rules, and grounding invariant.
Synthetic data only · POC for an MBA healthcare-innovation practicum · No real PHI · No automatic write to the record without human approval.
